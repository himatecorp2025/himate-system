# START-22.3 Acceptance — Commercial Automation & Partner Website Integration

## Scope

START-22.3 closes the commercial and integration chain after the accepted START-22.1 Control Plane and START-22.2 Partner Portal. It does not replace or reprogram partner websites. Existing partner sites integrate with HIMATE through the authenticated Connector Protocol and a configurable website-adapter contract.

## Commercial automation

### Explicit activation workflow
A new non-waived partner must satisfy this order before provisioning is allowed:

1. commercial terms exist;
2. commercial agreement is explicitly `AGREED` with a persistent reference;
3. activation-fee invoice evidence exists;
4. payment evidence or a receipt exists;
5. the activation license is verified `PAID`;
6. the Billing provisioning gate returns `allowed=true`;
7. Provisioning may proceed.

Reference/legacy partners may still use the already documented waiver path; a waiver must remain explicit and justified.

### Immutable module-period pricing
- each active module has activation-anchored 30-day periods;
- each partner/module/period has one immutable price snapshot;
- the snapshot resolves the Catalog price effective at the exact period start;
- Catalog price changes during a running period cannot change that period;
- the new price is eligible only for a later period start;
- missed Billing runs backfill all periods from activation using point-in-time Catalog history;
- base-package inclusion is snapshotted with the period.

### Itemized invoice ledger
- module periods create immutable pending `MODULE` invoice items;
- base service creates one immutable `BASE_SERVICE` item per partner service period;
- invoice generation attaches eligible pending module items;
- invoice `module_fee` and `total` derive from attached items, not live Catalog prices;
- invoice API responses expose their itemized lines;
- idempotent reruns never rewrite an already captured line-item amount.

### Billing event ledger
The database-backed immutable event stream includes at minimum:
- `COMMERCIAL_AGREEMENT_CONFIRMED`
- `COMMERCIAL_TERMS_UPDATED`
- `ACTIVATION_INVOICE_REGISTERED`
- `PAYMENT_EVIDENCE_REGISTERED`
- `LICENSE_PAID`
- `MODULE_ACTIVATED`
- `MODULE_PERIOD_STARTED`
- `MODULE_PERIOD_ENDED`
- `MODULE_RENEWED`
- `MODULE_CANCELLATION_SCHEDULED`
- `MODULE_CANCELLATION_WITHDRAWN`
- `INVOICE_ITEM_CREATED`
- `INVOICE_GENERATED`

Where an API mutation changes an authoritative Billing record, its corresponding event is written in the same database transaction when practical.

## Partner Website Connector

### No website rewrite
Partner websites remain independently owned applications. HIMATE provides an adapter configuration and Connector API surface. No partner-site source code is copied into the HIMATE database and no full partner website is generated by START-22.3.

### Website Adapter
Per partner/environment the control plane stores:
- adapter type: `GENERIC_HTTP`, `WORDPRESS`, or `CUSTOM_API`;
- partner website base URL;
- explicit allowed-domain list;
- capabilities;
- enabled state;
- minimized adapter configuration;
- `AGGREGATED_ONLY` privacy mode.

The authoritative partner primary domain must appear in the adapter allowlist. A mismatch fails closed.

### Credential-bound commercial state
`GET /connector/v1/commercial-state`:
- authenticates with the existing one-time-issued, hash-stored connector credential;
- derives partner and environment only from that credential;
- returns active module entitlements and versions;
- returns service-cycle dates and desired maintenance/configuration state;
- returns domain-binding and adapter metadata;
- does not return module prices, invoices, payment information or unrestricted personal information;
- advertises existing Connector endpoints for metrics, approved aggregated batches and reconciliation;
- retains the unified HIMATE seven-year retained-data policy already established in START-22.

## Internal administration UI
Partner Workspace exposes:
- commercial activation workflow;
- agreement status/reference;
- activation fee/payment readiness;
- workflow next action;
- immutable commercial billing events;
- Partner Website Adapter configuration;
- clear notice that the existing partner website is not being replaced.

The New Partner wizard records the agreement and activation-fee invoice before payment verification/provisioning.

## Required automated acceptance

1. Go tidy, vet, unit, race and service build.
2. Flutter analyze, Chrome tests and release web build.
3. Render Blueprint and Docker Compose topology validation.
4. Full START-01–22.2 historical regression suite.
5. START-22.3 dedicated commercial/integration smoke:
   - incomplete commercial workflow fails closed;
   - PAID is rejected before payment evidence;
   - agreement + invoice + payment evidence + PAID opens provisioning;
   - delayed first sync backfills 30-day snapshots;
   - current-period price stays immutable after Catalog repricing;
   - next period takes the later effective price;
   - itemized invoice uses the period snapshot, not live Catalog price;
   - cancellation creates the billing event;
   - required billing event types exist;
   - website adapter fails closed on primary-domain mismatch;
   - corrected adapter exposes credential-bound commercial state;
   - commercial-state omits price/invoice/payment data.
6. OpenAPI version is `0.8.3-start-22.3` and documents all new public/control-plane endpoints.
7. No START-23 work is included.

## Definition of Done

START-22.3 is DONE only when its PR has green Go, Flutter, Compose, complete START-01–22.2 regression, and the dedicated START-22.3 acceptance smoke. It may then merge to `develop`.

After that merge, development stops. The next activity is the separately requested full START-01–22.3 branch/develop/backend/frontend/security/privacy/load audit before any START-23 work.
